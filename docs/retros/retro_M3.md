## What should we stop doing? (6)

1. **Stop merging statistical code on a "synthetic-tested" label before a calibration check against the registry text.** The engine (201d8bf, 040e0df, merged 48d1076 at 20:23) shipped a GPD tail at fewer than 10 exceedances plus B = 1,000, while the registry says 10,000 permutations and GPD below 1e-4. That inflated null size 1.3-1.8x (h3a_fdr_diagnosis.md, size table). It surfaced only at 21:50, after FZ-C was frozen (02f62ee). The fix was cheap but touched every caller (H3a/H3b/H2/H1/lockbox).
2. **Stop letting the producing agent choose the error metric after writing the code.** The tests bounded pooled FDP, but the registered Benjamini-Bogomolov procedure controls the average over selected families (diagnosis, cause 2; pooled FDP is about 0.068 even with exact p). A second test asserted `false_pos <= 1` on one seed (holds in 69% of seeds; removed in 8fc91f6, D6). The metric should be written into the registry entry before the test exists.
3. **Stop stating firewall rules in prose that DESIGN does not actually enforce.** The rule "no proteomics before FZ-C" was already violated by contexts.py (read at 18:57), which DESIGN permits (D5; fzc_review §1). The reviewer also could not verify that no ad hoc process read BioPlex before 21:41, because APFS atime is useless. Only `require_frozen` and the import-graph test were enforceable. Encode every firewall as a guard or test (as in `test_part2_firewall.py`), and reconcile the prose with DESIGN before the pre-freeze commit f0f940e.
4. **Stop freezing secondary claims that have no chance baseline.** The infra notes were known before the FZ-C freeze: rewired stability is 0.84-0.90 for 3-4-gene clusters, above the observed 0.49 (zavg) and 0.36 (GLS), and the split-half criterion is flat (0.338-0.343 at k = 10). Yet "zavg more stable" still needed a downgrade to descriptive in D5 (fzc_review §5). Pair-level AP was also S x S, not genome-wide (N3). Drop or define the claim at pre-freeze.
5. **Stop running milestones with deferred items outside the tree's gating.** Map-to-map variability (20 bootstrap maps), FZ-X fills and the controls run are open but gate G2/Fig 2 only through a sentence in fzc_review §5. RESEARCH_TREE's header says "M3 done" while its own "Next" lists three unmet prerequisites, and the "Previous status (M2)" paragraph still says freeze is "scheduled as soon as the working tree is clean". Dead status text contradicts the live one (lesson 6 recurring). Give each deferral an explicit gate line in the tree and delete superseded status text.
6. **Stop leaving agent worktrees and implicit paths around.** There are six unmerged `worktree-agent-*` branches. FZ-C tiers/bridge (9498d05) were committed on one and reviewed from it, and the reviewer had to set `PART1_DIR` manually or `paths.PART1_ORIG` resolved inside `.claude/worktrees/` (fzc_review N4).
